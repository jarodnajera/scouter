| Scenario | Local instruction check |
| --- | --- |
| Established authorized addition | Core routine steps allow guarded exact acquisition without a mandatory proposal or redundant risk approval; verified native cooldown/build controls and direct advisory completion are prerequisites. Graph checks stay pending until after acquisition. |
| Unexpected script/dependency metadata | Missing or unexpected necessary metadata routes to staged artifact/source review and REVIEW; installation approval does not enable scripts. |
| Post-install advisory failure | Incomplete added/changed-graph coverage produces REVIEW and stops builds/imports/runners. Report installed/partial state and gaps; no automatic deletion or unwrapped retry. |
| Confirmed compromise with user insistence | BLOCK overrides approval, stops installation/execution and cannot be waived. |
| Yarn Classic | No native cooldown: explicitly outside routine eligibility. Keep Classic and request a scoped decision for gaps; no migration. |
| Python resolution and supplied pins | pip/uv requirements retain exact distributions, compatible wheel origins/hashes and build prevention. Reuse complete compatible reviewed pins; resolve only when needed. uv preserves interpreter and Python-download restrictions. |
| Routine grouped additions | Core allows compatible groups and shared/deduplicated lookups; retain workspace/category boundaries, graph review and partial-outcome reporting. |
| Fresh or unsupported native coverage | Staged review and scoped approval remain necessary; exact graph/cutoff safeguards cannot be replaced by global relaxation. Unsupported `sfw` coverage cannot be approved away. |

Source inspection is deliberately absent from routine review; declarations are not proof of behavior. Direct advisory evidence and native safeguards precede acquisition; added/changed graph advisories and firewall/diff inspection precede execution. These timing/depth changes are not qualified by older evaluation passes.
