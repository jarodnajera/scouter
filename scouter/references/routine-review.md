# Routine review

Use with the core for one established public package in an existing single-root project. Confirm official identity, consistent publisher evidence, mature artifacts, complete graph and static behavior evidence, and no unresolved concern; popularity alone is insufficient. Start provisionally, then escalate any failed eligibility check. Keep all five checks and Ready requirements.

## Shared preflight

Identify instructions, manager/version, manifests/locks, dependency category, target/environment, baseline, and local changes. Preserve stronger policy and existing tooling. Verify trusted executable paths before invoking help: project hooks/plugins and auto-downloading shims must not run implicitly. Check installed subcommand help and matching official configuration/source; help may omit configuration-only options. Verify effective settings, location/types/units, precedence, exclusions, and operation coverage. Printed settings do not prove enforcement. Uncertainty needs the [discrepancy procedure](package-manager-protections.md#resolve-version-discrepancies), not invented flags, upgrades, or trial installs.

Assess the trusted existing `sfw` launcher before first use each task. Its npm launcher can download/update its native binary; inspect that behavior and permitted network access. [Vendor documentation](https://docs.socket.dev/docs/socket-firewall-free) lists public-registry manager support, not every operation/source. Confirm planned artifact coverage. Mandatory telemetry includes coordinates, machine identifier, timing/errors, and potentially GitHub organization; it cannot be disabled. Documentation is not an independent traffic audit. If unavailable, unsupported, prohibited, or uncertain, stop and read [Socket operations](socket-operations.md). No fabricated opt-out, Git stripping, or temporary-directory privacy workaround. Package managers retain normal registry traffic; inspect routing/authentication first, without exposing tokens or silently stripping needed credentials.

## Review and acquire

1. Corroborate direct identity independently; compare installed or preceding stable versions and inspect relevant published manifests/artifact sources statically. Metadata or script suppression alone cannot establish behavior. Review dependency, publisher, script, executable, network, and credential changes. Missing necessary comparisons or suspicious changes need full review.
2. Extract the exact complete target graph locally: versions, edges, origins, integrity and relevant deltas. Use structured checks for transitives, investigating concrete signals rather than manually researching every package. Verify each artifact's release status and seven-day/stronger cutoff; locked entries and missing native coverage require exact-artifact dates plus graph preservation. Missing dates or fresh transitives remain REVIEW.
3. Complete exact-version/range advisory coverage for every applicable public coordinate. Prefer OSV querybatch: deduplicate locally extracted ecosystem/name/version inputs, map results to request order, respect limits, finish per-query pagination, and fetch advisory details for findings. Failed/partial/unsupported lookups remain gaps; completed empty results mean no known findings. Assess relevant malware reports. Never upload project metadata or implicitly invoke audit services.
4. Resolve through `sfw` without executing package code, using a verified proposal path. Inspect proposed graph/artifacts before acquisition; no supported path means REVIEW. Read only the applicable manager instructions below. Pin reviewed versions, preserve the graph, suppress unreviewed builds/scripts, and use compatible fresh task-owned caches. Do not purge shared caches. Reused caches/installed bytes may bypass download checks; disclose coverage. Check replacement/removal effects before clean/exact installs.
5. Under existing authorization, attempt guarded installation; inspect firewall output, graph and file/environment changes before any new code. Stop on warnings, failures or drift; report partial changes without unwrapped retries or automatic rollback. Use the core report; success proves neither full scanning nor functionality.

Reuse findings only within this task for unchanged coordinates/artifacts, graph, target, configuration and policy. Retain sources/times/gaps; refresh time-sensitive evidence before installation. Changes invalidate affected findings. Use [batch review](batch-review.md) for larger reuse/grouping.

## Manager instructions and escalation

Read: [npm](package-manager-protections.md#routine-npm), [pnpm or Yarn](yarn-pnpm.md), [pip](pip.md), or [uv](uv.md). Only that manager's sections apply. Python selected-wheel dates/hashes and separate proposal/install stages remain mandatory.

Outside eligibility, load detailed protection/Socket guidance and relevant [batch](batch-review.md), [first-install](first-install.md), [runner](one-shot-runners.md), [build](build-scripts.md), or [security-fix](security-fixes.md) workflow before proceeding. Workspaces, setup problems and suspicious changes need this escalation. Specialized reports require [reporting](reporting.md). Unsupported Poetry/pipx coverage is unchanged.
